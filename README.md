FastEnglish Demo (Expo)

一个英语学习 Demo：用带中英双语字幕的电影做精听——逐句跳转、单句循环、原声或合成音再听一遍、字幕时间轴微调。

运行前提
- Node.js 23.4 或更高（后端用了内置的 `node:sqlite`，更早的版本要加实验性标志）
- 已安装 npm
- 真机预览需要 iPhone/Android 上的 Expo Go

单独拆出来的三篇：
- [docs/手机上手.md](docs/手机上手.md)——每次开机跑什么、手机怎么扫码连上、出问题按什么顺序查
- [docs/部署与迁移.md](docs/部署与迁移.md)——日常启停命令、备份、换机器怎么搬
- [docs/数据从哪来.md](docs/数据从哪来.md)——字幕和单词分别从哪下载、哪些数据下一次就永久本地化

## 前后端分成两个进程

后端不再寄生在 Metro 上，得单独起。**两个都要开**：

```bash
npm install
npm run server   # 后端：数据库、片库、串流，默认 4000
npm run web      # 前端：默认 8081
npm run phone    # 要上手机就用这个替代 npm run web，见下方「上手机」
```

后端跑在**存放电影的那台机器上**——片库靠扫 `MOVIE_ROOT` 得到，视频也从那里按 Range 串流出去。在同一台机器上用浏览器看就是走 localhost，等同读本地盘；手机则走局域网。

前端不填地址时会自己猜后端位置：网页端拿当前主机名换 4000 端口，原生端拿 Expo 报的开发机 IP 换 4000 端口。部署到别的机器或改了端口时，在 `.env` 里填 `EXPO_PUBLIC_API_BASE=http://192.168.1.5:4000`。注意手机上不能写 `localhost`，那指向手机自己。

## 上手机

```bash
npm run server   # 别忘了，视频和数据都从它来
npm run phone    # 扫这个终端里的二维码
```

`npm run phone` 比 `npm run start` 多做一件事：把手机该连的地址钉死。

装了 Hyper-V、VirtualBox 或 WSL 的机器上会凭空多出几块虚拟网卡（172.x、192.168.56.x），Expo 挑网卡时挑中它们的话，二维码里给的地址手机根本路由不过去；更隐蔽的是前端猜后端地址也跟着 `hostUri` 走，于是扫码能进 App，一登录就转圈。脚本让内核自己说了算——朝外网地址开一个 UDP 套接字（不发包），按默认路由选出的源地址就是手机该连的那个，然后同时喂给 `REACT_NATIVE_PACKAGER_HOSTNAME` 和 `EXPO_PUBLIC_API_BASE`。`.env` 里显式填了 `EXPO_PUBLIC_API_BASE` 的话以 `.env` 为准。

启动时会先探一下后端在不在，不在就直接告诉你，省得到手机上才发现登录不了。

**别用 Expo 自带的 `--tunnel`**。它只转发 Metro 那个端口，后端的 4000 穿不过去，结果就是扫码能进、一登录就连不上。要出局域网请用下面的 `--public`。

## 出了局域网怎么用

```bash
npm run server         # 照常
npm run phone:public   # 两条 Cloudflare 隧道，手机在哪都能连
```

它起两条 [Cloudflare 快速隧道](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/)：一条给后端 4000，一条给 Metro 8081，各自拿到一个 `https://xxx.trycloudflare.com`。终端里会把两个地址都打出来，Expo Go 里手动输 Metro 那条就能进。不用账号、不用域名、不用在路由器上开端口，也不受运营商没给公网 IP 的影响——隧道是从你这台机器主动连出去的。

Metro 那条不能只把域名塞进 `REACT_NATIVE_PACKAGER_HOSTNAME`：那样拼出来的 bundle 地址是 `http://`，而快速隧道只认 https，手机取包会卡在重定向上。脚本设的是 `EXPO_PACKAGER_PROXY_URL`，它是给「Metro 蹲在 https 反代后面」准备的那个开关，会把清单里的 `bundleUrl` 整个换成隧道地址。

代价有三个，都不小：

- **域名每次重启都变**，得重新在 Expo Go 里输一遍。想要固定域名见下一节。
- **绕远路**。Cloudflare 就近挑边缘节点，实测落在洛杉矶，往返延迟从本机的 3 ms 涨到约 394 ms。连续播放不受影响（缓冲扛得住），但拖进度条、切句子会明显迟滞小半秒。
- **Cloudflare 免费额度不欢迎跑视频**。他们的服务条款第 2.8 条明确限制用免费服务分发大流量视频。听模式一小时 29 MB，没人会在意；看模式一小时 2 GB 以上，属于顶风作案。

带宽方面实测隧道能跑到 14.5 Mbps，看模式需要约 5 Mbps（`范海辛` 4.9、`源代码` 5.1、`反叛者` 1.3），够用。但真正省心的还是**听模式**——0.064 Mbps，读模式和写模式则完全不碰媒体流，在外面用这三个模式基本感觉不到是在远程。所以外网环境下模式默认就落在听模式，细节见后面「听模式」那节。

## 固定域名：Tailscale Funnel

```bash
npm run server
npm run phone:funnel
```

地址永远是这一对，连上一次就不用再管：

| | 地址 |
|---|---|
| Metro（手机连这个） | `https://<机器名>.<tailnet>.ts.net` |
| 后端接口 | `https://<机器名>.<tailnet>.ts.net:8443` |

不用买域名、不用迁 NS、手机上也不用装任何东西（Funnel 本身就是公网可达的）。配置存在 tailscaled 里而不是某个进程里，所以机器重启后依然在——`phone:funnel` 每次只是确认一下，不是重新建隧道。

Funnel 只允许 443、8443、10000 三个端口，所以两个服务按端口分而不是按路径分。用 `--set-path` 做路径分流的话 Tailscale 会把前缀吃掉，后端收到的就成了 `/health` 而不是 `/api/health`，对不上。

### 代价：带宽只有约 1 Mbps

官方文档只写「受不可配置的带宽限制」，不给数值。实测公网路径（用 `curl --resolve` 把域名钉到 Tailscale 的入口 IP，绕开本机 MagicDNS）：

| | Tailscale Funnel | Cloudflare 快速隧道 |
|---|---|---|
| 吞吐 | 0.7 ~ 1.4 Mbps | 14.5 Mbps |
| 一次完整请求 | 约 1460 ms | 约 394 ms |
| 域名 | 固定 | 每次重启都变 |

所以这是一道二选一：**要固定地址就用 Funnel，要带宽就用 `phone:public`**。

听模式只要 0.064 Mbps，余量二十倍；读模式和写模式压根不碰媒体流。**看模式要 5 Mbps，Funnel 跑不动，会卡。** 好在外网环境下默认就落在听模式（见「听模式」那节），Funnel 覆盖了四个模式里的三个。

想在外面也看画面，两条路：手机上也装 Tailscale 登同一个账号——**地址一模一样**，但流量走的是设备间直连而不是 Funnel 中继，瓶颈变回你家的上行带宽；或者临时切回 `npm run phone:public`。

### 本机测 Funnel 会测出假数据

装了 Tailscale 之后，MagicDNS 会把 `*.ts.net` 解析成 `100.x` 的内网地址。在这台机器上直接 `curl` 那个域名等于自己连自己，测出来一千多 Mbps，看着漂亮但和公网上的实际体验毫无关系。要测真的，先用 DoH 查一下公网解析（`https://dns.google/resolve?name=<域名>&type=A`，会拿到 `208.111.x.x` 这类 Tailscale 入口地址），再用 `curl --resolve 域名:端口:入口IP` 把连接钉过去。

### Windows 上的坑：后端卡在 NoState

`tailscale up` 登录成功之后，`tailscale status` 可能一直显示 `Tailscale is starting. Please wait.`，`status --json` 里 `BackendState` 是 `NoState`，这时候跑 `tailscale funnel` 会直接报 `unexpected state: NoState`。

原因是 Windows 上 `tailscaled` 服务把用户档案交给托盘程序管，托盘没起来后端就不会进入 Running。启动 `C:\Program Files\Tailscale\tailscale-ipn.exe` 就好了，几秒钟就转成 Running。服务显示 Running 完全不代表能用，这是最误导人的地方。

另外首次跑 `tailscale funnel` 时，它会打印一个 `https://login.tailscale.com/f/funnel?node=...` 让你在浏览器里给 tailnet 开 Funnel 开关，然后原地等着。如果你把它的输出通过管道喂给别的命令（比如 PowerShell 的 `Out-String`），这段提示会被缓冲住看不见，命令看起来就是莫名其妙地挂住了。

### 另一条路：Cloudflare 具名隧道

要固定域名又要带宽，就得上 Cloudflare 具名隧道：在 Cloudflare 托管一个自己的域名，`cloudflared tunnel login` 之后建一条具名隧道，配一个固定的 `hostname`。带宽和快速隧道一样（14.5 Mbps），还能在前面套一层 Cloudflare Access 做二次验证。

门槛是**得有一个整体托管在 Cloudflare 的域名**——免费版不支持只把一个子域名迁过去，那是 Business 套餐的功能。没有的话注册一个 `.xyz`/`.top` 一年十几块。

**留意 `~/.cloudflared/config.yml`**。cloudflared 默认会读它，那里要是躺着别的项目留下的 ingress 规则，优先级会压过命令行的 `--url`：请求进得来，却匹配不上任何一条 hostname，最后掉进兜底的 `http_status:404`。这个现象极具误导性——日志里白纸黑字「Registered tunnel connection」，域名也打出来了，可你怎么访问都是 404，而且是从 Cloudflare 边缘返回的，完全看不出跟本机的一个配置文件有关。所以 `scripts/cloudflared.mjs` 每次都临时造一个空配置传给 `--config`，把两者隔开。

嫌每次换地址麻烦的话，看下一节的 Tailscale Funnel——地址固定，代价是带宽。

### 挂上公网之前先把注册堵上

`.env` 里配 `FASTENGLISH_INVITE_CODE`：

```
FASTENGLISH_INVITE_CODE=你自己想一串
```

规则是**第一个账号随便建**（总得有人开张），**之后必须凭邀请码**。没配这一项就等于注册彻底关闭，登录页上连注册标签都不出现——宁可让你多配一行，也不能默认敞着。

这不是杞人忧天：在加这道闸门之前，`/auth/register` 是完全敞开的，任何人扫到地址就能开号、翻你共享出去的片子、往你硬盘上传文件。

顺带一提，端到端测试会在库里堆真账号。上公网前用 `node scripts/pruneUsers.mjs --keep 你的用户名` 先预演一遍，确认要删的都是测试留下的，再加 `--yes`。

要保多个账号，`--keep a,b` 和 `--keep a --keep b` 都行。另外只要待删名单里有账号名下还有数据，`--yes` 会被拒掉，得再补一个 `--force` —— `--keep` 少打一个名字实在太容易，而删掉就只能去 `data/` 翻备份捞。

### 怎么让 Expo Go 连上：扫码，别找输入框

新版 Expo Go 首页已经没有「Enter URL manually」那一栏了，只剩「Development servers」的说明文字和「Recently opened」列表。所以第一次连一台手机，走扫码：`npm run phone`、`phone:public`、`phone:funnel` 启动后都会在终端里画一个二维码，**用手机的系统相机去扫**（不是在 Expo Go 里扫，它自己的扫码入口也去掉了），iOS 会弹出提示问要不要用 Expo Go 打开。连上一次之后它就躺在「Recently opened」里，以后点一下就行。

要单独出一张码：

```bash
node scripts/qr.mjs https://主机名            # 打到终端
node scripts/qr.mjs https://主机名 code.png   # 顺便存成图片
```

二维码里装的**不是** https 地址，而是 `exps://主机名`。scheme 那个 s 是关键：[Expo 文档](https://docs.expo.dev/linking/into-your-app/)里写着 `exp://` 一律被换成 `http://`，只有 `exps://` 才换成 `https://`。隧道后面只有 https，用 `exp://` 的话 Expo Go 会拿明文去敲 TLS 端口，报的是 `The network connection was lost`，从字面上完全看不出跟 scheme 有关。

也别自作聪明加 `:443`。https 默认就是它；更要紧的是万一碰上不认 `exps` 的 Expo Go 版本退回了 http，不带端口是 `http://主机名` → 80 → Tailscale 那个 302 跳到 https，还能救回来，而写死 `:443` 就是明文打 TLS，直接死。

**Expo CLI 自己画的那个二维码在这种场景下是错的**，所以脚本自己画了一个。`UrlCreator` 检测到 https 代理时只把端口补成 443，scheme 仍然留着 `exp`，拼出来正好是连不上的那个形式。

顺带一提，`EXPO_PACKAGER_PROXY_URL` 在源码里标着 `@deprecated`，但 SDK 54 仍然在读，而且它是唯一能把清单里的 `bundleUrl` 整个换成隧道地址的开关。只设 `REACT_NATIVE_PACKAGER_HOSTNAME` 拼出来的是 `http://`，手机取包会卡住。

**第一次打开要等两三分钟。** iOS 的开发包 6.6 MB，实测走 Funnel 拉完用了 152 秒。转圈的时候别以为死了。之后 Expo Go 有缓存会快些，但每次改代码重新打包还得再等。嫌慢就用 `phone:public`（14.5 Mbps，代价是地址每次变）。

### Expo Go 里试不出来的两件事

- **锁屏听**。后台播放要靠 `app.json` 里 expo-video 插件往 Info.plist 写 `UIBackgroundModes=audio`，而 config plugin 只在真正出包时才生效，Expo Go 用的是它自己那份 Info.plist。想要这个功能得走开发构建（`npx expo run:ios` 需要 Mac，或者用 EAS Build）。
- **.mkv 的看模式**。iOS 的播放器不认这个封装，点开只有黑屏。听模式不受影响——服务端用 ffmpeg 抽成 m4a 再发；读模式和写模式压根不碰视频。想在手机上看画面就先转成 mp4。

## 多用户

第一次打开是登录页，一个用户都没有时默认停在注册。每个人有自己的学习列表、收藏、注释和已掌握的词，互相看不见；片库是共用的一份，因为它就是磁盘上那些文件。

第一个账号之后，能不能注册取决于 `.env` 里的 `FASTENGLISH_INVITE_CODE`：配了就多一栏邀请码，没配就整个关掉。细节见上面「挂上公网之前先把注册堵上」。

密码用 Node 内置的 `crypto.scrypt` 加盐哈希后存库，参数一并写进哈希串，将来调高成本不用让老用户重设密码。登录态是存在 `sessions` 表里的随机令牌而不是 JWT——自建服务最需要的是能立刻把人踢下线，JWT 签发之后在过期前撤不掉。

### 账号面板

学习列表和学习页的右上角都是自己的名字，点开就是账号面板：

- 学习统计：在学几部、收藏几句、注释几条、掌握几个词。这些都在服务端，换台设备登上来还是这些
- 修改密码：要验旧密码。光凭令牌就能改密码，等于谁摸到你没锁屏的机器谁就能接管账号
- 退出其它设备：在别人机器上登过又忘了退，从自己这台一次撤干净。会话存在表里，撤销是即时的
- 退出登录：只清这台设备上的登录，学习记录一条不少

改完密码会自动把其它设备的登录一并作废，发起改密码的这台不受影响——不然刚输完新密码就被弹回登录页，还得再输一遍。退出和退出其它设备都要在原地点第二下确认，不用系统弹窗，因为 `Alert` 在 react-native-web 上和原生对不齐。

数据全在 `data/fastenglish.db`（SQLite，WAL 模式）。换机器时把 `data/` 整个拷走就完成迁移。这个目录已经在 `.gitignore` 里，**里面有密码哈希和所有人的学习记录，别提交**。

从文件版升级上来的话，老数据这样导入：
```bash
npm run migrate -- --user 你的用户名
```
它只读 `vocab/*.json`，不会动原文件，跑第二遍也不会重复插入。

## 学习列表

登录后先看到学习列表，两个页签：

- **我在学**——自己挑进来的片子，记着上次看到第几秒和用的哪份字幕，点进去自动续播
- **片库**——所有能看到的片子，点「加入学习」收进前一个页签

点任意一行直接进学习页，不用再去文件选择框里翻。学习页顶栏左上角回到列表。

### 片子怎么进来

两条路，区别在于**归属**：

| | 放哪 | 归谁 | 谁看得见 |
|---|---|---|---|
| 拷进片库目录 | `MOVIE_ROOT`，默认 `media/` | 无主 | 所有用户 |
| 应用里点「上传视频」 | `data/uploads/<用户 id>/` | 上传者 | 默认只有自己 |

片库目录不配也能用——`media/` 会自动建出来，把视频拖进去点「重新扫描」就出现了。已经有整理好的电影收藏时，在 `.env` 里把 `MOVIE_ROOT` 指过去。

上传适合后端不在自己这台机器上的情况（比如后端跑在 NAS，你在手机上）。**如果后端就跑在存着电影的那台电脑上，别用上传**——那只是把文件从一个目录复制到另一个目录，白白多占一份磁盘，直接配 `MOVIE_ROOT` 就好。

上传走的是裸字节流而不是 multipart，网页端能看到进度百分比。几个 GB 的片子传起来该多久还是多久，取决于网速。

### 共享

自己上传的片子默认是私有的，列表里标着「私有」。点「共享」之后所有人都能在片库里看到它、加进自己的学习列表、正常播放，卡片上会显示是谁共享的。随时可以「取消共享」，收回后它会从别人的学习列表里消失。

各人的收藏、注释、已掌握的词始终是自己的——共享的只是片源，不是学习记录。

扫描来的公共片库没有主人，任何人都改不了它的可见性，也删不掉。上传的片子只有上传者本人能删，删除时磁盘上的文件一并清掉。

## 界面

打开后是学习界面本身，选片和搜字幕都收在右上角的「视频与字幕」里，点开是浮层，字幕就位后自动收起：

- 左侧：画面（字幕叠在上面）、播放控制条、台词列表
- 右侧：当前句，以及这句里值得学的单词

屏幕窄于 980 时（手机、竖屏平板）改成上下排：画面留在上面，台词和单词折成标签页，再加一个直通「全片单词」的入口。顶栏也跟着换排法——片名和那串老长的字幕文件名挪到第二行，按钮才不至于被顶出屏幕，尤其是最右边的账号。

台词上三个动作分得很开：**单击选中**（送到右侧讲解，画面不动）、**双击放一遍**（放完这一句就停，仍然钉在这句上）、**按播放键从选中的那句起连着放**。琢磨一句和往下看是两件事，一个键管一件。选中期间列表不再跟着播放自动滚，免得正读着的行被滚走。

台词列表跟随播放自动滚动，但只滚它自己，画面始终留在原位。

## 使用方式

视频源支持三种：
- 网络地址：粘贴 http/https 链接后点「加载网址」
- 本地文件：点「选择本地视频」，网页端走文件选择框，真机走系统文件选择器
- 打包资源：默认关闭，见下方说明

字幕支持 `srt` / `vtt` / `ass`（含 `ssa`），可以从字幕网址加载，也可以选择本地字幕文件。双语字幕的两种常见形态都能识别：同一条字幕里中英各占一行，或中英是时间轴相同的两条字幕。点「示例视频与字幕」可以直接看到效果。

字幕加载后：
- 播放时字幕叠在画面上，可随时隐藏中文只留英文
- 台词列表逐句列出，单击选中送到右侧讲解，双击放一遍这句，点行尾的「跟读」让机器把这一句念给你听
- 字幕与片源版本对不齐时，用 `±1s` 粗调、`±0.25s` 微调整体平移

## 再听一句用谁的声音

「跟读」永远是机器念给你听——行尾那枚、控制条上的 `R`，两处都一样，不随任何开关改名。想听原片就双击那一行，原声档下会放一遍这句原片。一个按钮跟着档位改名，按下去之前拿不准会听到什么。

控制条上的「发音」是个下拉，管的是**双击台词、上/下一句、收藏连播**这几件事：

- **原声**（默认）：跳到这句开头放原片，放到句尾自己停住。真人的语调、连读、情绪都在里面，练听力靠的是它
- **合成音**：把画面按停，用 TTS 念。吐字清楚、语速可以压慢，一句里哪个词没听清能拿它对答案；不挑片源，跨片也能念

合成音档下多一枚「语速」按钮，点一下在 `0.6x → 0.75x → 0.9x → 1.0x` 之间轮转。原片的播放速度不受它影响——所以从原声切到合成音时节奏会变，压慢本来就是合成音的用处，这枚按钮是让你自己找那个点。

两档的区别不止在声音上。合成音档的意思是**别动画面**：双击台词、按「上一句/下一句」和 `←`/`→` 都只念不跳，画面停在原地。合成音档下的上/下一句是从当前选中的那句往前后数的，因为画面停着，播放进度早就不代表你在看哪一句了。

**按播放键 = 从选中的那句起顺着往下放。**两档下都成立，区别只在放的是画面还是念的声音：

- 原声档：跳到选中那句的开头接着往下播。播放头已经在这句里（或刚放完停在句尾）就不倒回去——那是暂停之后接着放，不是又挑了一句
- 合成音档：一句接一句念到片尾，圈了循环段落就只在段内绕圈。画面全程不动，但播放头跟着念到的那句挪，所以字幕、行高亮、自动滚动照旧跟得上，随时切回原声就接着这儿看。停下来有两条路：再按一次播放键，或者点控制条上的「■ 停止朗读」

单词、短语和词典例句永远走合成音，也不受语速档位影响——片子里没有对应的声音可对比，单个词压到 0.6x 听着发飘。

原声档下「放到句尾就停」是靠记一个刹车点实现的，播放器本身只会一路播下去。用户自己点了别的句子或者按了播放，这个约定当场作废，不会莫名其妙停一下。圈了循环时双击不设这个刹车点——循环要绕回段首，两边同时动手的结果是刚绕回去就被按停。

## 循环播放

两种循环，同一时刻只有一种生效：

- 单句循环：点「单句循环」或按 `L`，播到当前句结尾跳回句首。手动切句时循环目标跟着走
- 自定义段落：在台词行上点某句的「段首」，它后面所有句子的按钮都变成「段尾」等你收口，点一下这一段就反复播

段首段尾只在台词行上，控制条里没有——圈一段总得先找到那两句，手已经在行上了，再跑回控制条按一下纯属多走一趟。键盘上的 `[` `]` 还留着，圈的是当前正播的那句。

圈定后区间内的句子标着「段首 · 共 N 句」「段中 · 第 i/N 句」「段尾」，左侧一根绿竖线把整段连起来。只点了段首时不会开始循环，否则播放会被锁在那一句、走不到段尾。圈定后控制条上会显示「循环 6 句 · 02:59 - 03:20」，可以随时「重播」跳回段首，或按 `Esc` 取消。

网页端支持键盘操作（焦点在输入框里、或整页都在等你敲字的写模式下不生效）：

| 按键 | 作用 |
| --- | --- |
| 空格 | 播放 / 暂停 |
| ← / → | 上一句 / 下一句（合成音档下只念不跳） |
| `R` | 跟读当前句（合成音） |
| `L` | 单句循环开关 |
| `C` | 中文字幕开关 |
| `[` / `]` | 把当前句设成段首 / 段尾 |
| `Esc` | 取消循环 |

没有字幕时，视频会按 12 秒等间隔切段，列表退化为片段跳转，真机上还会显示片段缩略图。

## 四种模式

控制条上的「模式」下拉里是四种用法。看和听是原地换个放法，读和写会盖上整屏，退出后回到刚才那一档——所以下拉显示的始终是看或听。

摊开四个按钮并排放，光「模式」这一组就占掉控制条小半行，而它们本来就是互斥的四选一；收进下拉之后每一档还能跟一句说明，不能选的那档（听模式要片库里的片子，读写要有字幕）也说得出为什么。

| 模式 | 干什么 | 适合 |
| --- | --- | --- |
| 看模式 | 画面 + 台词 + 单词面板 | 精听一句、抠一个词 |
| 听模式 | 只放音轨，画面收起 | 走路、通勤，也省 45 倍带宽 |
| 读模式 | 整片台词排成文章 | 通读剧情、扫一遍生词的上下文 |
| 写模式 | 听写和抄写两种练法 | 检验到底听清了没有、把句子敲进手里 |

### 听模式

只听不看的时候，「听模式」会把画面收起来，改放服务端单独抽出来的音轨。

这不只是把画面藏起来——藏起来一点带宽都省不了，容器里音视频是交织存放的，按 Range 取一段字节画面的数据也在里面。第一次进听模式时后端会用 ffmpeg 把音轨抽成 64kbps 单声道 AAC 存到 `data/audio/<片子 id>.m4a`，之后播的就是这个文件。

实测一部 4.8 GB / 2 小时 11 分的片子：音轨 65 MB，播放时约 13 KB/s，而看画面时约 580 KB/s，**省了 45 倍**。抽取本身约 100 秒，只读服务器本地磁盘，不走网络；抽完会自动切过去，在那之前放的还是原片，界面上会照实说明。同一部片子只抽一次。

顺带解决一件事：mkv 里的 DTS/TrueHD 音轨浏览器根本解不了，重编码成 AAC 之后反而放得出来。

画面收起后台词列表拿到多出来的高度，当前句用大字单独显示，循环、跟读、收藏、单词面板全都照常——音轨的时间戳和原片完全一致。随时点「看模式」切回去，播放位置两边都接得住。

音质档位由 `FASTENGLISH_AUDIO_BITRATE` / `FASTENGLISH_AUDIO_CHANNELS` 控制，默认 `64k` / `1`。

只有片库里的片子能用听模式：抽音轨要读服务器上的原片，本机临时选的文件和粘贴的网址都做不到，这时按钮是灰的。

**默认开不开跟着网络环境走**。`src/lib/api.ts` 里的 `REMOTE` 看后端地址是不是私网：localhost、`10.x`、`192.168.x`、`172.16-31.x`、`*.local` 算内网，其余（公网域名、隧道给的 `trycloudflare` 域名、Tailscale 的 `100.64/10`）一律算外网。在外网默认落在听模式，在家默认看模式——出门时默认反了，一小时就是 2 GB 流量。

两种环境**各记各的选择**（`fastenglish.listen.remote` 和 `.local` 两个键）。只存一个键的话，你在家关掉听模式，出门又得手动开一次，等于白做。模式下拉在外网时会把两边的流量代价直接写在提示里（「一小时 2 GB」「一小时 29 MB」）。

### 读模式

一句一行的字幕读起来像流水账，段落感全靠停顿。读模式按两句之间空了多久断段：空得够久就是换场、换话题的地方，正好是分段的位置。944 句的片子在 5 秒档下排成 212 段，每段四五句。

「分段」按钮在 2s / 5s / 10s / 20s 之间轮转——不同片子的说话节奏差得远，只能自己调到读着顺。另有个 20 句的硬上限：一场连珠炮似的对话能几百句不带喘气的，光看停顿会排出一大坨。

**排版**两档，默认**成段**：同一段的句子接成一片连续的文字，读起来是文章而不是字幕表。每句仍是各自可点的，换行交给排版，不再一句占一行。切到**逐句**则回到一句一行一块，带高亮方框——想把某一句单独拎出来看时用它。

三档语言：**英文** / **中文** / **中英**。中英同屏时，整段英文接成一片，整段中文跟在它底下，中间一条细线隔开——两片字挨在一起会被看成一段。只看一种语言时就只有那一片。

试过按句排：一句英文和它的中文捆成一小块横着排，图的是每句中英左边缘对齐。实际读起来不如整段连排——块宽由最长的那一边撑开，句子长短不齐时块与块之间豁着大小不一的空档，一段话被切成了一格格的表。

中文句间会补个空格：中文字幕常常不带句末标点，直接接起来会读成「没事吧肖恩肖恩听着」，断不出这是几个人在说几句话。整段都没有译文时（字幕里确实有这种段落）标一句「这一段没有中文」，不然只剩个光段头。

分页：底部页码条翻页，「每页 N 段」在 3 / 5 / 8 / 12 / 20 之间轮转，默认 5 段。改分段秒数或每页段数都回到第一页——那时候页码指的已经不是同一批内容了。

**自动翻页**（就是播到哪一段、页面自己翻到哪一页）默认开着，只在换段时动——逐句滚的话读到一半页面就被拽走了。

手动翻页时它会先停下，翻回正在播的那一页又自动续上。一直跟着是在抢方向盘：片子每往前走一段就把页码拽回去，想翻回开头重读根本翻不动。可翻一下就永久关掉也不对——翻两页看看，回头播放早跑到别处去了，人还傻等在这一页，还以为坏了。所以只把「翻走」当成暂时离开：这期间底部会浮出一条「正在播第 12 段（第 4 页）· 点这里跟过去」，点一下回去，或者自己翻回那一页，都算归位。

「播放 原声 / 播放 合成音」管的是底部那颗播放键放谁的声音。播放条被这一屏整个盖住了，开关只能跟过来——不然进了读模式就被锁死在进来之前选的那档上。没片源时只有合成音，这个开关不出现。

每个段头带「▶ 原声」和「跟读」，放的只有这一段：原声放到段尾就停，合成音逐句念完这一段就停，都不会一路播下去。念着的时候底部播放键变成「■ 停止朗读」。

点段落里的任意一句就跳过去接着往下播，页面不会被关掉，正播的那句高亮。底部还有上一句 / 播放暂停 / 下一句和「回到正在播」，手机上放不下就折成两行，不会被顶出屏幕。

### 写模式

两种练法，顶上一按就换：**听写**（听着写，答案藏着）和**抄写**（照着敲，原文摆着）。练的不是一回事——听写练的是听出来，抄写练的是手熟和拼写。

#### 听写

一句一句来：听 → 写 → 对答案。

进来自动放一遍当前这句（「自动放」可关），原声和合成音各一个按钮。写完按回车对答案，再按回车翻下一句，手不用离开键盘。

批改是逐词对齐后再比的，不是按位置一个一个比：漏了一个词之后按位置比，后面全都会错位成红的，一句话只错一个词却看着满盘皆输。对齐之后结果分四种——绿色是对的，红色是拼错的（括号里跟着正确答案），灰色带下划线是漏写的，划掉的是多写的。大小写和标点不算错，`it's` 和 `its` 算错（那是个值得较真的区别）。

提示分四级，一级一级给：**无** → **中文** → **首字母**（`I c____ n____ a____`）→ **答案**。看过答案这句就不计分，否则统计里全是 100%。

顶上是进度：`已默写 34 / 944 · 平均 82%`，加一根进度条和「跳到没写过的」。每句记的是最好的那次成绩，重写只会往上走。

#### 抄写

照着原文一个字一个字敲下来，像打字通那样边敲边对。原文一直摆在眼前，敲到哪绿到哪，敲错的当场标红，还没敲到的是灰的。想连着音一起记，段上还有「▶ 原声」和「合成音」。

**按段抄，不按句抄。** 一句一句地喂，敲完一句就翻篇，练的是打字；成段地摆在眼前，一段话里的搭配和语序才跟着手一起过一遍。分段沿用读模式那套停顿判据，再加一道「每段 N 句」的闸（3 / 5 / 8 / 12，默认 5）——一段几十句的连珠炮敲下来只会让人放弃。换段长后按抄到的那一句重新落位，不会跳回开头。

输入框紧贴在原文下方，两块的字号、字间距、左内边距完全一样：敲到第几个字，眼睛往上一抬就是原文的同一列。输入框是多行的，回车在这儿不是换行而是交卷——原文里没有换行，敲进去只会算成错字。

顶上四个数一直亮着：**用时** / **正确率** / **速度**（字/分）/ **本轮 x / N 段**。第一个字母落下才开表，别让「准备一下」的时间也算进成绩；速度要等表走够 3 秒才报，否则刚敲两个字就能外推出几千字每分的荒唐数字。

正确率只看新敲进去的那几个字：退格改对不会抹掉刚才敲错的事实，否则一路退格重来就能刷出 100%。一整段一字不差地敲完会自动进下一段，手不用离开键盘；敲错了不自动走，留着让人退回去改。想略过没敲完的按回车。

**每轮 N 段**在 2 / 5 / 10 / 20 之间轮转，默认 5。抄满一轮弹成绩单（正确率、速度、用时、抄了几句、敲对多少字符），也可以随时「结束本轮」提前交卷；半路退出去不会白扔，已经抄完的那几段照样记一笔。

**抄写记录**留最近 30 条，倒序排，每条写着时间、句数、正确率、速度、用时，可以清空。

两种练法的进度都存在本机（AsyncStorage，按用户和片子分开），退出再进来接着上次那儿。听写写到哪、抄写抄到哪各记各的，两边不互相拽。没上服务端是有意的：这是自己跟自己较劲的练习，换台设备重头写一遍并不亏，为它加一张表、一套接口、一份同步逻辑，代价远超它值的那点。

## 单词学习

右侧列出当前这句里值得学的词。先下载词典（约 65 MB，一次就够）：

```bash
npm run fetch-dict
```

拉的是 [ECDICT](https://github.com/skywind3000/ECDICT)（MIT）的 `ecdict.csv` 和 `lemma.en.txt`，存进 `dict/`，不进版本库。下完重启 `expo start`。

每张单词卡片包含：

- 原形与音标。台词里是 `ran`，卡片给的是 `run`，并注明「片中写作 ran」
- 这句话里的意思。`She ran a restaurant` 中 `ran` 是动词，所以先给动词义项（管理、经营）
- 「它还能这样用」列出其他词性的意思（`n. 跑, 赛跑, 奔跑的路程`），并配一条那个意思的例句
- 「片中其他出处」把这个词在本片其他台词里的用法列出来。点例句就跳到片中那一句；只想听一句的话，右上角「▶ 原声 / 跟读」就地放，不用跳走
- 「标记掌握」记住这个词，已掌握的词默认从列表里隐藏

难度分三档：「全部」不过滤，「适中」滤掉柯林斯 4 星以上和词频前 1200 的词，「只看难词」再严一档。

### 全片单词

点右上角「全片单词」摊开整部电影的词。手机上右侧那栏是折进「单词」标签页的，这个入口跟着缩进了角落等于没有，所以窄屏的标签栏里另给一个「全片单词 506」。

表头一行给出这一档的进度：`已掌握 340 / 506` 加一根进度条，三个筛选按钮各自带数字（`未掌握 166` / `已掌握 340` / `全部 506`）。分母跟着难度走——「只看难词」下你关心的就是这些难词学到哪儿了，跟全片几百个词没关系。

词铺成矩阵，一格一个：单词、片中出现次数、一行释义、掌握开关，左上角一个 `▶`。几行几列按窗口现算（1440 宽的屏上是 7 × 11，iPhone 上是 2 × 9），铺满一屏就是一页，不滚动。这一屏是挂着不卸载、靠隐藏收起来的，收起来时量不到尺寸，所以量到之前先按窗口估一版——只认实测的话，重新显示时万一没补一发布局回调，每页就装 0 个词，打开是一片空白。点格子从底部摊开完整词条（音标、其他词性、片中其他出处、词典例句）；词条走浮层而不是插进格子中间，插进去整页的行列会当场重排，正在看的词就跑到别处去了。

底部页码条翻页：`第 3 / 7 页 · 每页 7 × 11`。换难度、换筛选、换排序都回到第一页。

排序三档轮转：**出现最多**（默认，先啃高频的）、**片中先后**（跟着剧情走）、**字母序**（查特定词时好找）。

「看和念」三档管的是格子里露出什么、连播时念什么，两件事同一个开关：

| 档位 | 格子里 | 念的 |
| --- | --- | --- |
| 单词 | 只有英文 | 只念单词 |
| 释义 | 只有中文 | 只念释义 |
| 全部（默认） | 都有 | 都念 |

拆成两个开关没意义——看得到单词却念的是释义这种组合谁也用不上。合成一个之后三档各自成了一种复习法：只看单词回想意思、只看中文回想单词、全都摊开对答案。前两档一格只剩一行，矮下来一页能多装一半的词（7 × 11 → 7 × 15）。

连播：顶部「▶ 连着念 N 个」从头念下来，格子左上角的 `▶` 从这个词往后念，正念的那格会亮起来。**念到下一页的词，页面自己翻过去**——不翻的话一串念下来屏幕还停在第一页，听着的词根本不知道是哪个。

中英是分开两段念的——TTS 按语言选发音人，中英混在一段里两边都不像话。

词条里点例句会跳到片中那句台词，这时屏幕右下角挂出一条「← 回到单词 crucifix」：整页是收起来而不是卸载的，点回去看到的还是刚才那一页、刚才那个词条。自己点「返回」关掉的不留这条——那是主动走的，不需要退路。

掌握状态存在 `vocab/mastery.json`，跨电影共享，学会的词换部片子不会再冒出来。`vocab/` 属于个人学习记录，不进版本库，目录由开发服务器按需创建。

### 短语会自动标出来

只讲单词是不够的：`call it a day` 每个词都认识，合起来的意思却猜不到。ECDICT 的 77 万条词条里有 36 万条是多词条目，所以短语识别不需要大模型——当前句里认出的短语会单独列在生词上方。

匹配时做了四件事，缺一不可：台词里的动词是变位的，`showed up` 要还原成 `show up` 才查得到；`turned him down` 中间夹着宾语，得跨过去才认得出 `turn down`；`put up with this` 会同时命中 `put up`、`up with`、`with this` 等好几个，按长度从长到短抢占词的位置才能只留下 `put up with`；最后滤掉 `have to`、`out of`、`next week` 这类语法胶水，否则真正的习语会被淹没。

短语查询搭词典查询的同一趟扫描，不额外读那个 63 MB 的文件。

## 收藏与注释

台词列表每一行右侧都有这两个入口，顶栏对应两个页签，同一个页面里可以互相切换：

- 「☆ 收藏」记下这一句，收藏列表按时间倒序，点任意一条回到那一句
- 「✎ 注释」写下自己的理解——词典解释不了语气、指代和文化梗。写完的注释会直接显示在那句台词下面，不用点开也能看见

两者都记着句子属于哪部片、第几句、时间点和当时的原文。同一部片直接跳回去；换了片子只能先把那部片的字幕切回来，因为浏览器给本地视频的地址是一次性的，得重新选一次片源。

列表右上角的「连着放」把当前这一列句子从上往下过一遍，放到哪句哪张卡片就亮起来，随时能停。每张卡片上也有单独的播放按钮。当成复习列表用。

这里同样有「原声 / 合成音」开关和语速档位，跟台词列表共用一份设置。原声要读片源，所以只有当前这部片的句子放得出来；收藏跨着好几部片，其余的会自动退回合成音，列表上方会写明有几句是这种情况。合成音不挑片源，想把整列连着过一遍，它更省事。

数据存在 `vocab/favorites.json` 和 `vocab/notes.json`。

### 例句从哪来

ECDICT 只有释义没有例句，所以例句来自三处，按贴合度排序：

1. 本片其他台词——最贴合语境，零成本，但只有词在片中出现多次时才有
2. [百词斩词义数据](https://github.com/lyc8503/baicizhan-word-meaning-API)——带中文翻译，覆盖约一万个常用词
3. [Free Dictionary API](https://dictionaryapi.dev)——按词性分组，覆盖广但全是英文，用来给「它还能这样用」配例句

后两者联网取一次就缓存进 `vocab/examples/`，之后离线可用。

### 词义区分做到什么程度

判断词性不需要大模型：`compromise` 是纯 JS 的词性标注库，能认出 `She ran a restaurant` 里的 `ran` 是动词、`I went for a run` 里的 `run` 是名词。ECDICT 的中文释义本身就按词性分行，两者一对，就能给出「片中是动词用法，它作名词时是这个意思」。

做不到的是同一词性内部的细分。`run` 作动词有跑步、经营、运转、竞选几十个意思，不借助大模型没法判断片中那句用的是哪一个。所以对比只到词性这一层，同词性的多个义项会一并列出，由你自己对照。词性判断本身也有约一成误判，比如 `This is the last shot we have` 里的 `shot` 会被当成动词。

## 在线搜索字幕

「在线搜索字幕」面板可以按片名从 OpenSubtitles 直接拉字幕，中英各选一条后自动按时间轴配对成双语。

先配置密钥：在 https://www.opensubtitles.com 注册，于 Profile → API Consumers 生成 key，然后复制 `.env.example` 为 `.env` 并填入：

```
OPENSUBTITLES_API_KEY=你的key
```

`.env` 不进仓库，改完需要重启 `expo start` 才会生效。

几点使用要点：
- 中文名和英文原名都能搜。用中文名搜时，英文字幕那一路会先从中文结果里取出该片的英文原名再搜一次，界面上会显示「已按英文原名《Source Code》搜索英文字幕」
- 搜索不消耗额度，只有下载消耗；免费账号每天 100 次，中英各下一份算 2 次
- 结果按片名相关度和下载量排序，但同名影片仍可能混入，下载前看一眼每条下面的片名与年份
- 不同压制版本的时间轴可能整体偏移，双语对不齐时用 `±1s` / `±0.25s` 平移
- 中文字幕通常不翻译语气词，所以约一成英文句会没有中文，这是字幕本身的差异

## 字幕会存进 subtitles/ 目录

加载过的字幕都会以视频文件名为索引存成 `subtitles/<视频文件名>.json`，下次选到同一个视频自动套用，不必重新搜索，也不再消耗下载额度。在线下载的、本地导入的、从网址加载的字幕都一样对待。「已下载的字幕」卡片会列出存过的记录，可以直接点用或删除，删除会连同文件一起删掉。

一部电影约 1000 句、占 90 KB 左右。文件是普通 JSON，可以直接看、手动改、复制到别的机器。`subtitles/` 不进版本库——下载来的字幕是第三方版权内容，也暴露看过哪些片。

配了 `.env` 里的 `MOVIE_ROOT` 之后，字幕会改存到视频文件旁边，同时生成一份通用双语 `.srt`，PotPlayer、VLC 之类的播放器可以直接加载。

浏览器不能直接写磁盘，所以读写由后端代劳（`scripts/subtitleStore.js`），网页端和原生端走同一组端点。

请求为什么要经过后端转发：OpenSubtitles 的网关按 User-Agent 拦截浏览器（会返回 `kong-user-agent-block`），而浏览器禁止 JavaScript 修改 User-Agent，网页端无法直连。所以后端挂了一个中间件（`scripts/openSubtitlesProxy.js`）代为转发，密钥也因此只留在服务端进程，不会打进客户端 bundle。

## 打包内置视频

`src/lib/bundledVideo.ts` 默认不引入任何视频文件。Metro 会静态解析 `require` 的路径，一旦文件不存在，整个 bundle 都打不出来，所以不要写死一个不存在的路径。需要内置视频时把文件放进 `video/`，再按该文件里的注释取消注释并填上文件名。大文件会显著拖慢打包与安装，长视频建议用本地文件选择或网络地址。

## 已知限制

- `expo-video-thumbnails` 没有网页端实现，缩略图只在真机可用
- `expo-video` 的内嵌字幕轨接口在网页端是空实现，所以字幕层由应用自己渲染，这也是能做逐句控制的前提
- 网页端的语音合成走浏览器 Web Speech API，音色与真机不同
- 单词功能要求字幕带英文原文，只有中文的字幕拆不出词
- 所有数据接口都在后端（`npm run server`），它没起来时前端只有登录页
- 视频不转码，原样发出去。片源若是 iOS/浏览器解不了的封装或编码（MKV + H.265、DTS 音轨），在那些端上放不出来——换成 MP4 + H.264，或者用听模式（音轨会重编码成 AAC）
- 听模式只取第一条音轨，多音轨的片子（国配、评论音轨）目前选不了
- 音轨缓存按片子累积，一部约 60MB，片库大了要留意 `data/audio/` 占的磁盘
- 客户端代码别用太新的标准 API。手机上跑的是 Hermes，缺不少浏览器早就有的东西——`AbortSignal.timeout()` 就没有，用了会抛「is not a function」。这种坑在网页端一点征兆都没有，上了真机整个功能哑掉还查不出所以然。请求超时统一走 `src/lib/api.ts` 里的 `withTimeout()`（`AbortController` 加定时器，哪儿都认）

## 后续方向

字幕的获取（现成字幕文件转换、语音识别生成时间轴、硬字幕 OCR）都属于离线预处理，产物是统一的时间轴 JSON：

```ts
type Segment = { id: number; start: number; end: number; en: string; zh?: string };
```

应用端只消费这个结构，不关心它来自哪条路径。
