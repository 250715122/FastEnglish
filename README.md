FastEnglish Demo (Expo)

一个英语学习 Demo：用带中英双语字幕的电影做精听——逐句跳转、单句循环、点句跟读、字幕时间轴微调。

运行前提
- Node.js 20 或更高（本项目在 Node 24 上验证通过）
- 已安装 npm
- 真机预览需要 iPhone/Android 上的 Expo Go

## 两种预览方式

浏览器（改代码最快，存盘即刷新）：
```bash
npm install
npm run web
```
默认地址 http://localhost:8081 。

真机（功能最全，缩略图只有真机可用）：
```bash
npm run start
```
手机与电脑处于同一局域网时，用 Expo Go 扫描终端二维码即可。若网络不通（跨网段、AP 隔离、公司网络），改用穿透模式：
```bash
npm run start -- --tunnel
```

两种方式可以同时开：启动后在终端按 `w` 打开网页端，手机同时扫码。

## 界面

打开后是学习界面本身，选片和搜字幕都收在右上角的「视频与字幕」里，点开是浮层，字幕就位后自动收起：

- 左侧：画面（字幕叠在上面）、播放控制条、台词列表
- 右侧：当前句，以及这句里值得学的单词

台词列表跟随播放自动滚动，但只滚它自己，画面始终留在原位。

## 使用方式

视频源支持三种：
- 网络地址：粘贴 http/https 链接后点「加载网址」
- 本地文件：点「选择本地视频」，网页端走文件选择框，真机走系统文件选择器
- 打包资源：默认关闭，见下方说明

字幕支持 `srt` / `vtt` / `ass`（含 `ssa`），可以从字幕网址加载，也可以选择本地字幕文件。双语字幕的两种常见形态都能识别：同一条字幕里中英各占一行，或中英是时间轴相同的两条字幕。点「示例视频与字幕」可以直接看到效果。

字幕加载后：
- 播放时字幕叠在画面上，可随时隐藏中文只留英文
- 台词列表逐句列出，点任意一句跳转过去，点「跟读」用 TTS 慢速朗读该句
- 字幕与片源版本对不齐时，用 `±1s` 粗调、`±0.25s` 微调整体平移

## 循环播放

两种循环，同一时刻只有一种生效：

- 单句循环：点「单句循环」或按 `L`，播到当前句结尾跳回句首。手动切句时循环目标跟着走
- 自定义段落：播到想要的开头按「段首」（`[`），播到结尾按「段尾」（`]`），这一段就会反复播

这两个按钮在控制条和台词行上各有一份。在行上圈选更省事：点某句的「段首」后，它后面所有句子的按钮都会变成「段尾」等你收口，不用来回跑到控制条。圈定后区间内的句子标着「段首 · 共 N 句」「段中 · 第 i/N 句」「段尾」，左侧一根绿竖线把整段连起来。

只按了段首时不会开始循环，否则播放会被锁在那一句、走不到段尾。圈定后控制条上会显示「循环 6 句 · 02:59 - 03:20」，可以随时「重播」跳回段首，或按 `Esc` 取消。循环区间内的台词在列表里带浅绿底色，首尾两句标着「段首」「段尾」。

网页端支持键盘操作（焦点在输入框里时不生效）：

| 按键 | 作用 |
| --- | --- |
| 空格 | 播放 / 暂停 |
| ← / → | 上一句 / 下一句 |
| `R` | 跟读当前句 |
| `L` | 单句循环开关 |
| `C` | 中文字幕开关 |
| `[` / `]` | 设段首 / 设段尾 |
| `Esc` | 取消循环 |

没有字幕时，视频会按 12 秒等间隔切段，列表退化为片段跳转，真机上还会显示片段缩略图。

## 单词学习

右侧列出当前这句里值得学的词。先下载词典（约 65 MB，一次就够）：

```bash
npm run fetch-dict
```

拉的是 [ECDICT](https://github.com/skywind3000/ECDICT)（MIT）的 `ecdict.csv` 和 `lemma.en.txt`，存进 `dict/`，不进版本库。下完重启 `expo start`。

每张单词卡片包含：

- 原形与音标。台词里是 `ran`，卡片给的是 `run`，并注明「片中写作 ran」
- 这句话里的意思。`She ran a restaurant` 中 `ran` 是动词，所以先给动词义项（管理、经营）
- 「它还能这样用」列出其他词性的意思（`n. 跑, 赛跑, 奔跑的路程`），并配一条那个意思的例句
- 「片中其他出处」把这个词在本片其他台词里的用法列出来，点一下直接跳过去
- 「标记掌握」记住这个词，已掌握的词默认从列表里隐藏

难度分三档：「全部」不过滤，「适中」滤掉柯林斯 4 星以上和词频前 1200 的词，「只看难词」再严一档。点右上角「全片单词」进入整部电影的单词表，同样支持按未掌握 / 已掌握筛选和难度切换。

掌握状态存在 `vocab/mastery.json`，跨电影共享，学会的词换部片子不会再冒出来。`vocab/` 属于个人学习记录，不进版本库，目录由开发服务器按需创建。

### 短语会自动标出来

只讲单词是不够的：`call it a day` 每个词都认识，合起来的意思却猜不到。ECDICT 的 77 万条词条里有 36 万条是多词条目，所以短语识别不需要大模型——当前句里认出的短语会单独列在生词上方。

匹配时做了四件事，缺一不可：台词里的动词是变位的，`showed up` 要还原成 `show up` 才查得到；`turned him down` 中间夹着宾语，得跨过去才认得出 `turn down`；`put up with this` 会同时命中 `put up`、`up with`、`with this` 等好几个，按长度从长到短抢占词的位置才能只留下 `put up with`；最后滤掉 `have to`、`out of`、`next week` 这类语法胶水，否则真正的习语会被淹没。

短语查询搭词典查询的同一趟扫描，不额外读那个 63 MB 的文件。

## 收藏与注释

台词列表每一行右侧都有这两个入口，顶栏对应两个页签，同一个页面里可以互相切换：

- 「☆ 收藏」记下这一句，收藏列表按时间倒序，点任意一条回到那一句
- 「✎ 注释」写下自己的理解——词典解释不了语气、指代和文化梗。写完的注释会直接显示在那句台词下面，不用点开也能看见

两者都记着句子属于哪部片、第几句、时间点和当时的原文。同一部片直接跳回去；换了片子只能先把那部片的字幕切回来，因为浏览器给本地视频的地址是一次性的，得重新选一次片源。

数据存在 `vocab/favorites.json` 和 `vocab/notes.json`。

### 例句从哪来

ECDICT 只有释义没有例句，所以例句来自三处，按贴合度排序：

1. 本片其他台词——最贴合语境，零成本，但只有词在片中出现多次时才有
2. [百词斩词义数据](https://github.com/lyc8503/baicizhan-word-meaning-API)——带中文翻译，覆盖约一万个常用词
3. [Free Dictionary API](https://dictionaryapi.dev)——按词性分组，覆盖广但全是英文，用来给「它还能这样用」配例句

后两者联网取一次就缓存进 `vocab/examples/`，之后离线可用。

### 词义区分做到什么程度

判断词性不需要大模型：`compromise` 是纯 JS 的词性标注库，能认出 `She ran a restaurant` 里的 `ran` 是动词、`I went for a run` 里的 `run` 是名词。ECDICT 的中文释义本身就按词性分行，两者一对，就能给出「片中是动词用法，它作名词时是这个意思」。

做不到的是同一词性内部的细分。`run` 作动词有跑步、经营、运转、竞选几十个意思，不借助大模型没法判断片中那句用的是哪一个。所以对比只到词性这一层，同词性的多个义项会一并列出，由你自己对照。词性判断本身也有约一成误判，比如 `This is the last shot we have` 里的 `shot` 会被当成动词。

## 在线搜索字幕

「在线搜索字幕」面板可以按片名从 OpenSubtitles 直接拉字幕，中英各选一条后自动按时间轴配对成双语。

先配置密钥：在 https://www.opensubtitles.com 注册，于 Profile → API Consumers 生成 key，然后复制 `.env.example` 为 `.env` 并填入：

```
OPENSUBTITLES_API_KEY=你的key
```

`.env` 不进仓库，改完需要重启 `expo start` 才会生效。

几点使用要点：
- 中文名和英文原名都能搜。用中文名搜时，英文字幕那一路会先从中文结果里取出该片的英文原名再搜一次，界面上会显示「已按英文原名《Source Code》搜索英文字幕」
- 搜索不消耗额度，只有下载消耗；免费账号每天 100 次，中英各下一份算 2 次
- 结果按片名相关度和下载量排序，但同名影片仍可能混入，下载前看一眼每条下面的片名与年份
- 不同压制版本的时间轴可能整体偏移，双语对不齐时用 `±1s` / `±0.25s` 平移
- 中文字幕通常不翻译语气词，所以约一成英文句会没有中文，这是字幕本身的差异

## 字幕会存进 subtitles/ 目录

加载过的字幕都会以视频文件名为索引存成 `subtitles/<视频文件名>.json`，下次选到同一个视频自动套用，不必重新搜索，也不再消耗下载额度。在线下载的、本地导入的、从网址加载的字幕都一样对待。「已下载的字幕」卡片会列出存过的记录，可以直接点用或删除，删除会连同文件一起删掉。

一部电影约 1000 句、占 90 KB 左右。文件是普通 JSON，可以直接看、手动改、复制到别的机器。`subtitles/` 不进版本库——下载来的字幕是第三方版权内容，也暴露看过哪些片。

配了 `.env` 里的 `MOVIE_ROOT` 之后，字幕会改存到视频文件旁边，同时生成一份通用双语 `.srt`，PotPlayer、VLC 之类的播放器可以直接加载。

浏览器不能直接写磁盘，所以读写由开发服务器上的中间件代劳（`scripts/subtitleStore.js`），网页端和原生端走同一组端点。因此这项功能同样依赖 `expo start` 的开发服务器。

请求为什么要经过本地代理：OpenSubtitles 的网关按 User-Agent 拦截浏览器（会返回 `kong-user-agent-block`），而浏览器禁止 JavaScript 修改 User-Agent，网页端无法直连。所以 `metro.config.js` 在开发服务器上挂了一个中间件（`scripts/openSubtitlesProxy.js`）代为转发，密钥也因此只留在服务端进程，不会打进客户端 bundle。这也意味着搜索功能依赖 `expo start` 的开发服务器，静态导出的产物里不可用。

## 打包内置视频

`src/lib/bundledVideo.ts` 默认不引入任何视频文件。Metro 会静态解析 `require` 的路径，一旦文件不存在，整个 bundle 都打不出来，所以不要写死一个不存在的路径。需要内置视频时把文件放进 `video/`，再按该文件里的注释取消注释并填上文件名。大文件会显著拖慢打包与安装，长视频建议用本地文件选择或网络地址。

## 已知限制

- `expo-video-thumbnails` 没有网页端实现，缩略图只在真机可用
- `expo-video` 的内嵌字幕轨接口在网页端是空实现，所以字幕层由应用自己渲染，这也是能做逐句控制的前提
- 网页端的语音合成走浏览器 Web Speech API，音色与真机不同
- 单词功能要求字幕带英文原文，只有中文的字幕拆不出词
- 词典查询和例句抓取都走开发服务器中间件（`scripts/dictStore.js`、`scripts/vocabStore.js`），静态导出的产物里不可用

## 后续方向

字幕的获取（现成字幕文件转换、语音识别生成时间轴、硬字幕 OCR）都属于离线预处理，产物是统一的时间轴 JSON：

```ts
type Segment = { id: number; start: number; end: number; en: string; zh?: string };
```

应用端只消费这个结构，不关心它来自哪条路径。
