# 部署与迁移

换机器怎么搬，日常怎么启停。手机侧的连接步骤在 [手机上手.md](手机上手.md)。

---

## 一、日常启停

### 启动

要开**两个**终端，各跑一条，都得一直开着：

```bash
npm run server        # 后端：数据库、片库、串流、字幕、词典。占 4000
npm run phone:funnel  # Metro + 二维码。占 8081
```

第二条按场景换：

| 命令 | 用在什么时候 | 地址 |
|---|---|---|
| `npm run web` | 只在这台机器上用浏览器 | `http://localhost:8081` |
| `npm run phone` | 手机和电脑在同一个 WiFi | 局域网 IP，会变 |
| `npm run phone:funnel` | 人在外面，要固定地址 | 固定，约 1 Mbps |
| `npm run phone:public` | 人在外面，非要看画面 | 每次重启都变，14.5 Mbps |

顺序无所谓，但后端没起来时前端能打开、一登录就转圈。`phone` 系列启动时会自己探一下后端，没应答会打印一行警告。

### 停止

正常情况在各自的终端里 **Ctrl+C** 就行。

终端已经关了但进程还赖着（再启动会报 `EADDRINUSE`）时：

```bash
npm run stop              # 停 4000 和 8081，顺带收拾残留的 cloudflared
npm run stop -- --funnel  # 再把 Tailscale Funnel 也撤掉
```

`npm run stop` 可以重复跑，没在跑的会直接说「本来就没跑」。

**Funnel 要单独一步**，因为它的配置存在 tailscaled 里，不属于任何一个进程——关终端、重启电脑都还在。只有 `tailscale funnel reset`（也就是 `npm run stop -- --funnel`）能把公网地址收回去。下次跑 `npm run phone:funnel` 会自动配回来。

### 看现在是什么状态

```bash
node --input-type=module -e "for (const [n,u] of [['后端','http://localhost:4000/api/health'],['Metro','http://localhost:8081/status']]) { try { const r=await fetch(u); console.log(n, r.status); } catch { console.log(n, '不通'); } }"
```

## 二、备份

```bash
npm run backup
```

生成 `data/backups/fastenglish-<时间戳>.db`，**服务开着跑也安全**，不用停机。这一个文件就是全部用户数据（账号、收藏、注释、掌握的词、片库记录），当前约 80 KB。

### 为什么不能直接拷 data/fastenglish.db

因为库开着 WAL，最近的写入还躺在 `fastenglish.db-wal` 里没并回主文件。这不是理论风险，实测过：

| 拷贝方式 | 读出来的用户数 |
|---|---|
| 活库（能看到 WAL） | 2 |
| **只拷 `.db` 主文件** | **71** |
| `npm run backup` | 2 |

只拷主文件会把之前清理掉的 69 个测试账号全都"复活"。而且拷出来的文件能正常打开，只是内容是旧的——**丢得无声无息**，等发现时已经晚了。

`npm run backup` 用的是 `VACUUM INTO`，产出一个已经合并完、自带完整 schema 的单文件副本，备份完还会立刻打开验一遍再报数。

要是非要手动拷，就得把 `fastenglish.db`、`fastenglish.db-wal`、`fastenglish.db-shm` **三个一起**拷走。

## 三、迁移到新机器

### 先搞清楚哪些要搬

| 目录 | 当前大小 | 要搬吗 | 说明 |
|---|---|---|---|
| 代码 | — | git clone | 都在仓库里 |
| `.env` | — | **要** | 不在仓库里，得手抄。见下 |
| `data/fastenglish.db` | 0.1 MB | **要** | 唯一不可再生的东西，用 `npm run backup` |
| `data/uploads/` | 8.4 GB | 看情况 | 用户上传的片子。不搬的话片库里会指向不存在的文件 |
| `data/audio/` | 127 MB | 不用 | 听模式的音轨缓存，会自动重抽 |
| `dict/` | 65 MB | 不用 | `npm run fetch-dict` 重新拉 |
| `subtitles/` | 0.3 MB | 建议搬 | 下过的字幕，不搬就得重下（每天只有 5 次额度） |
| `vocab/examples/` | 0.1 MB | 建议搬 | 372 个例句缓存，不搬会重新联网查 |
| `node_modules/` | 327 MB | **绝对不要** | 里面有平台相关的二进制（ffmpeg），拷过去会跑不起来 |
| `media/`、`video/` | — | 看情况 | 你自己的片源 |

一句话版本：**代码走 git，`.env` 手抄，`npm run backup` 出来那个文件带走，其它都能重建。**

### 步骤

**1. 新机器上装 Node**

必须 **23.4 或更高**。后端用了内置的 `node:sqlite`，更早的版本要加实验性标志才能跑。

```bash
node -v
```

**2. 拉代码、装依赖**

```bash
git clone https://github.com/250715122/FastEnglish.git
cd FastEnglish
npm install
```

`npm install` 会下载 `ffmpeg-static` 对应这个平台的二进制（听模式抽音轨要用），所以这一步需要联网，而且**不能把旧机器的 `node_modules` 拷过来顶替**。

**3. 拉词典**

```bash
npm run fetch-dict
```

从 GitHub 拉 63 MB 的 `ecdict.csv` 和 2 MB 的 `lemma.en.txt`。国内网络直连 raw.githubusercontent.com 常失败，脚本自带 ghproxy 和 jsdelivr 两个备用源会自动重试。文件已存在且大小正常时会跳过，想强制重下加 `--force`。

**没有这一步的后果**：应用能打开，但右侧词面板一直报词典不可用。

**4. 写 .env**

照着 `.env.example` 复制一份改名成 `.env`，至少填这几项：

| 变量 | 要不要填 | 说明 |
|---|---|---|
| `OPENSUBTITLES_API_KEY` | 想在线搜字幕就要 | 从旧机器的 `.env` 抄过来，或去 opensubtitles.com 的 Profile → API Consumers 重新生成 |
| `FASTENGLISH_INVITE_CODE` | **挂公网就必须填** | 留空 = 有人之后彻底关闭注册。不填又挂到公网，等于让任何扫到地址的人开号 |
| `MOVIE_ROOT` | 有整理好的片库才填 | 留空则用项目下的 `media/`，把视频拷进去点「重新扫描」 |
| `FASTENGLISH_DATA_DIR` | 想放大盘上才填 | 默认项目下的 `data/`。上传功能很吃磁盘 |
| `EXPO_PUBLIC_API_BASE` | 一般不填 | 不填会自己猜。`phone` 系列脚本会自动覆盖它 |

`.env` 里留空的项等于没配，后端不会拿空值去覆盖真实的环境变量。

**5. 放回数据库**

把旧机器 `npm run backup` 出来的那个文件拷到新机器，改名放好：

```bash
mkdir data
cp fastenglish-20260820-022109.db data/fastenglish.db
```

注意**别**同时拷旧的 `-wal` 和 `-shm` 文件过来，备份文件是自洽的，旁边多出来的旧 WAL 反而会让 SQLite 困惑。

跳过这一步也能跑，只是从零开始：第一个注册的账号不需要邀请码。

**建表不用管**，schema 迁移在后端连库时自动跑（`server/db.js` 里的 `MIGRATIONS`），按 `PRAGMA user_version` 记进度，跑过的不会重复执行。

> `npm run migrate` **不是**建表。它是一次性的旧数据导入，把文件时代的 `vocab/*.json`（那时还没有用户概念）搬进数据库并归给某个人，用法是 `npm run migrate -- --user 用户名`。新机器上用不着。

**6. 搬可选的缓存**

```bash
# 下过的字幕，不搬就得重下，而免费账号每天只有 5 次下载额度
cp -r subtitles/ 新机器/subtitles/

# 例句缓存，不搬会重新联网查（每个词一次）
cp -r vocab/ 新机器/vocab/
```

如果旧机器配过 `MOVIE_ROOT`，字幕是存在**视频文件旁边**的（`<片名>.fastenglish.json`），跟着片源一起搬就行，项目下的 `subtitles/` 只放兜底的那部分。

**7. 起服务验一遍**

```bash
npm run server
```

另开一个终端：

```bash
npm run web
```

打开 `http://localhost:8081`，用旧账号登录，随便进一部片子，确认右侧词面板能出中文释义——能出就说明数据库、词典、鉴权三样都对上了。

### 外网访问（可选）

想在新机器上也用固定域名，装 Tailscale 并登同一个账号：

```bash
winget install tailscale.tailscale     # Windows
tailscale up --hostname=fastenglish
npm run phone:funnel
```

域名会变成 `fastenglish.<你的 tailnet>.ts.net`。注意 tailnet 里主机名不能重复，旧机器还在线的话得先改名或下线。

## 四、迁移之后容易忘的事

- **手机上的 Expo Go 要重新连**。地址换了，「Recently opened」里的旧条目是死的，得重新扫码。
- **旧机器记得收摊**：`npm run stop -- --funnel`，否则那台还挂在公网上。
- **`.env` 不在 git 里**，最容易漏。漏了的表现是：能登录，但搜字幕报错、挂公网时注册大门敞开。
- **别把 `node_modules` 拷过去**。ffmpeg 的二进制是分平台的，拷过去听模式会崩，而报错信息指向的地方跟真正的原因八竿子打不着。
