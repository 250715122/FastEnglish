# 字幕和单词到底从哪下载

一句话：**前端从不直连任何第三方站点，全部经过你自己的后端。** 手机和浏览器只跟 `EXPO_PUBLIC_API_BASE` 那个地址说话。

---

## 字幕

```
手机 ──► 你的后端 /api/opensubtitles/* ──► api.opensubtitles.com
                    │
                    └──► 落盘：视频旁边的 .fastenglish.json + .zh-en.srt
                              （没配 MOVIE_ROOT 时落在项目的 subtitles/）
```

**搜索和下载都是后端代发的**（`scripts/openSubtitlesProxy.js`，挂载于 `server/index.js:96`）。前端只知道 `/api/opensubtitles/search` 和 `/api/opensubtitles/download` 两个路径（`src/lib/subtitleSearch/openSubtitles.ts:7`）。

这么设计有两个原因：一是 OpenSubtitles 按 User-Agent 拦浏览器，网页端直连会吃 403；二是 **API key 只在后端读**（`process.env.OPENSUBTITLES_API_KEY`），变量名没有 `EXPO_PUBLIC_` 前缀，Expo 不会把它打进客户端包里。

下载分两跳，第二跳去 OpenSubtitles 的 CDN 取字幕正文，**也在服务端**（`openSubtitlesProxy.js:78`），手机全程不碰外部域名。

**字幕存在服务器磁盘上，不在手机上。** 手机端唯一持久化的东西是登录令牌。

**同一部片第二次打开不会重新下载。** `App.tsx:1000` 先查缓存，命中直接用；文件名对不上时还会用归一化片名做模糊匹配（`subtitleCache.ts:86`）；两者都落空才去搜。

---

## 单词

分成三件事，只有一件会出网。

### 1. 词表：前端本地算的，不联网

「这片子里有哪些词」是前端用 [compromise](https://github.com/spencermountain/compromise) 在本地分词算出来的（`src/lib/vocabulary/extract.ts:62`，`buildWordIndex` 在 `:87`），纯 JS，不调大模型也不请求任何接口。

全片词表这一次请求不小：一部 944 句的片子要上传 42 KB（词表 + 全部台词，短语识别需要），下载 400 KB（1000 多条释义）。响应走 gzip，实际过网约 86 KB。

在外网这是最容易卡的一个请求。曾经因为不压缩、又多发了三个界面根本没用的字段（`definition`、`pos`、`exchange`，占四成体积），664 KB 压在 13~28 KB/s 的 Funnel 上要 25~67 秒，直接撞穿前端 60 秒的超时——而报错写的是「确认后端还在跑」，方向指反了。现在压完 5 秒左右。

### 2. 释义和短语：后端读本地 CSV，不联网

前端把词表和句子整批发给 `/api/dict/lookup`（`src/lib/vocabulary/dictionary.ts:72`），后端流式扫本地的 `dict/ecdict.csv`（`scripts/dictStore.js:12`）。这个文件是 `npm run fetch-dict` **一次性**从 GitHub 拉下来的，之后所有查询都是本地磁盘 I/O。

短语和习语（`call it a day` 这类）也在这一步解决：ECDICT 七十多万条里有一半是多词条目。后端切 2~6 词的候选、按词形还原扩展、长的优先占位去重叠（`scripts/dictStore.js:211-295`），再把 `have to`、`a lot of` 这种语法胶水过滤掉（`:71`）。**不联网，也不用大模型。**

### 3. 例句：唯一真正出网的一环，仍然是后端发的

`/api/dict/examples`（`src/hooks/useExamples.ts:23`）由**后端**去访问两个源：

| 源 | 地址 | 给什么 |
|---|---|---|
| 百词斩（GitHub 镜像） | `cdn.jsdelivr.net` | 带中文翻译的例句 |
| Free Dictionary API | `api.dictionaryapi.dev` | 按词性分组的纯英文例句 |

结果缓存到 `vocab/examples/<word>.json`（`scripts/dictStore.js:394` 读、`:441` 写），**同一个词只会查一次，之后永远读缓存**。

有个副作用要知道：`:441` 是无条件写，查空了也会写一个空壳文件下来，所以**失败过的词不会自动重试**。想让某个词重查，删掉 `vocab/examples/` 下对应的 json。

还有一点：只有右侧「当前句」那个面板会触发查例句（`src/components/WordPanel.tsx:75`）。**翻全片单词表不会产生任何网络请求**——`WordbookScreen` 里的卡片没有传 `examples`。

## 汇总：运行时会碰到哪些外部域名

| 域名 | 谁发起的 | 什么时候 |
|---|---|---|
| `api.opensubtitles.com` + 它的下载域 | **后端** | 每次搜字幕、下字幕 |
| `cdn.jsdelivr.net` | **后端** | 每个新词查一次例句 |
| `api.dictionaryapi.dev` | **后端** | 同上 |
| `media.w3.org` | **手机/浏览器** | 只在点「加载示例」时 |
| 你自己粘的视频网址 | **手机/浏览器** | 手动输入时 |
| 你的后端 | **手机/浏览器** | 其余一切：登录、片库、串流、音轨、字幕、词典、例句、收藏笔记 |

只在装环境时出网、跑起来之后不碰的：`raw.githubusercontent.com` / `ghproxy.net`（`npm run fetch-dict` 拉词典用）。

一次下载后永久本地化的：**词典**（`dict/`）、**字幕**（视频旁边或 `subtitles/`）、**例句**（`vocab/examples/`）。用户数据（收藏、笔记、掌握度）本来就在后端 SQLite 里，从不出网。

朗读用的是 `expo-speech`，走手机或浏览器自带的 TTS 引擎，要不要联网取决于系统的语音引擎，不由这个项目决定。

## 鉴权：全部接口都要登录

这几组接口原先是不套登录的，理由是「不含个人数据」。挂上 Tailscale Funnel 之后这个理由不成立了，2026-08-20 从公网实测确认过是敞着的，已经收紧：

| 接口 | 当时谁都能干什么 |
|---|---|
| `GET /api/subtitles/list` | 看到你存过哪些片子的字幕，等于泄露片单 |
| `GET /api/opensubtitles/search` | 白嫖你的 OpenSubtitles 额度（免费账号每天只有 5 次下载） |
| `POST /api/dict/lookup` | 用你的词典 |
| `POST /api/dict/examples` | 驱使你的后端替陌生人去外网抓数据 |

现在 `requireAuth` 挂在这三个前缀上（`server/index.js`），只剩 `/api/health` 和 `/api/auth/status` 公开——前端登录前要靠它们判断服务器活着没、开不开放注册。

`requireAuth` 只读请求头不碰 body，所以不影响后面那几个中间件用 `request.on('data')` 读原始流；OPTIONS 在更前面的 CORS 环节就返回了，预检不会撞上 401。

自查一遍（换成你自己的域名）：

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://<你的域名>:8443/api/subtitles/list
```

**401 才是对的。** 返回 200 说明改动没生效，多半是后端没重启。
